# แผนการพัฒนาและชุดคำถามเจาะลึก (Specifications & Grill-Me Questions)
## ระบบ AutoMail Insurance - Management Web Portal

อ้างอิงจากแบบดีไซน์ Mockup และฟังก์ชั่นการทำงานที่ได้รับมอบหมาย
เอกสารนี้รวบรวมรายละเอียดของทุกหน้าจอ โครงสร้างฐานข้อมูล (Google Sheets) API สถาปัตยกรรมระบบ และคำถามสำคัญเพื่อสรุป Requirement ให้ชัดเจนก่อนลงมือพัฒนา

---

## 📑 สรุปโครงสร้างหน้าจอทั้งหมด (Page Breakdown)

### 0. หน้า Login (Authentication & Authorization)
- **ระบบยืนยันตัวตน:** Google OAuth 2.0 (Google Sign-In)
- **การตรวจสอบสิทธิ์ 2 ชั้น (Two-tier Authorization Gate - ยืนยันแล้ว):**
  1. **Tier 1 (Google Drive Permission):** ตรวจสอบผ่าน Google Drive API (`drive.permissions.list`) ว่าบัญชี Google ที่ Login เข้ามา ได้รับการแชร์สิทธิ์เข้าดู/แก้ไขใน `SPREADSHEET_ID` จริง
  2. **Tier 2 (Internal Role Mapping):** ตรวจสอบเทียบกับรายชื่อในแผ่นงาน `Users` (หรือ `Config_Users`) ใน Google Sheet เพื่อดึง Role (`Admin` หรือ `Viewer`) และตรวจสอบว่าสถานะเป็น `Active`
  3. หากผ่านทั้ง 2 ขั้นตอน จะออก JWT Session Token ให้เข้าใช้งาน หากไม่ผ่าน จะแสดงข้อความปฏิเสธการเข้าถึงพร้อมระบุเหตุผล (เช่น ยังไม่ได้แชร์ไฟล์ หรือยังไม่มีชื่อในระบบ)

---

### 1. หน้า Dashboard (ภาพรวมระบบ)
- **Header:** แถบค้นหาหลัก, การแจ้งเตือน (Notification Bell), แสดงโปรไฟล์ผู้ใช้พร้อม Role (Admin / Viewer)
- **Date Filter:** ตัวเลือกช่วงเวลา (เช่น `01/10/2026 - 31/10/2026`)
- **Metric Cards (4 การ์ด):**
  1. *อีเมลทั้งหมด*: จำนวนรวม (พร้อม % แนวโน้มเทียบกับเดือนก่อน)
  2. *ส่งต่อบริษัทประกันแล้ว*: จำนวนที่ระบบ Auto-Forward สำเร็จ (สีเขียว)
  3. *Needs Review*: จำนวนอีเมลที่รอการตรวจสอบ (สีส้ม)
  4. *รอดำเนินการ*: จำนวนอีเมลค้างส่ง / รอ Retry (สีเทา/ฟ้า)
- **Table รายการอีเมลล่าสุด:** แสดง 5-10 รายการล่าสุด พร้อมปุ่ม "ดูรายละเอียด" และเมนูด่วน

---

### 2. หน้า รายการอีเมล (Inbox Mail)
- **Status Tabs:** ทั้งหมด (All), ส่งต่อแล้ว (Forwarded), Needs Review, รอดำเนินการ (Pending)
- **Search & Filter:** ค้นหาตาม Booking No., อีเมลผู้ส่ง, หัวข้อ
- **ตารางแสดงผล:** เช็คบ็อกซ์เลือกหลายรายการ, วันที่/เวลา, ผู้ส่ง, หัวข้อ, ป้ายสถานะ (Badges), ปุ่ม "ดูรายละเอียด"
- **Bulk Actions:** เช่น เลือกเพื่อส่งต่อพร้อมกัน หรือมาร์กสถานะ

---

### 3. หน้า/หน้าต่าง รายละเอียดอีเมล (Email Detail & Thread Chain)
- **Header Bar:** ปุ่ม "← กลับ", หัวข้ออีเมล (พร้อม Booking No.), ป้ายสถานะ, ปุ่ม Action "ส่งต่ออีกครั้ง (Re-forward)"
- **Meta Information:**
  - จาก (From), ถึง (To), วันที่/เวลา (Date/Time)
  - Message-ID (RFC 2822), In-Reply-To, References
  - Thread ID สำหรับติดตามห่วงโซ่อีเมล
- **แท็บเนื้อหาภายใน:**
  1. *เนื้อหาอีเมล (Body):* สลับดู HTML Preview หรือ Plain Text
  2. *ไฟล์แนบ (Attachments):* แสดงการ์ดไฟล์แนบ พร้อมขนาดไฟล์ ไอคอนประเภทไฟล์ และปุ่มดาวน์โหลด/พรีวิว
  3. *ประวัติการทำงาน / Thread Chain:* แสดงไทม์ไลน์การส่ง การตอบกลับ (Reply) และการส่งต่อไปยังบริษัทประกัน

---

### 4. หน้า Master Data (Whitelisted Customers / Partners)
- **ตารางข้อมูล:** ลำดับ (No.), อีเมล (Email), ชื่อลูกค้า/หมายเหตุ (Name/Notes), สถานะ (Active / Inactive), วันที่บันทึก
- **ฟังก์ชั่น:**
  - ปุ่ม "+ เพิ่มรายการ" (Modal ฟอร์มกรอกชื่อ อีเมล เบอร์โทร สถานะ)
  - แก้ไขข้อมูลเดิม (Edit Modal)
  - สลับสถานะเปิด/ปิด (Toggle Active/Inactive) หรือลบรายการ (Delete)
  - ซิงค์กับ Google Sheet แผ่นงาน `Master_Data`

---

### 5. หน้า Needs Review (ไม่พบใน Master Data)
- **เงื่อนไข:** อีเมลที่ส่งเข้ามามีหัวข้อ (Subject) ตรงกับแพทเทิร์นระบบประกัน (เช่น มี `[BK-xxxx]`, `[แจ้งเตือน]`, `ขอข้อมูลทำประกัน`) แต่ **อีเมลผู้ส่ง (Sender) ไม่อยู่ใน Master Data**
- **ฟังก์ชั่นเฉพาะ:**
  - แสดงจำนวนรายการที่ต้อง Review ชัดเจน
  - ปุ่ม "ตรวจสอบ" เปิดดูรายละเอียด
  - **Action พิเศษ:** ปุ่มด่วน "+ เพิ่มเข้า Master Data ทันที" (One-click Whitelist) เพื่อให้อีเมลนี้ส่งต่ออัตโนมัติได้ทันที
  - ปุ่ม "ปฏิเสธ / ละเว้น (Ignore / Reject)"

---

### 6. หน้า Email Template (เทมเพลตอีเมล)
- **ตารางรายการ:** ชื่อเทมเพลต, หัวข้อ (Subject), ประเภท (ส่งถึงลูกค้า / ส่งถึงบริษัทประกัน), สถานะ, ปุ่มแก้ไข
- **Template Editor (โหมด Dual-Mode รองรับทั้งผู้ใช้ทั่วไปและ Developer):**
  - **โหมดแก้ไขแบบง่าย (Simple Form Editor - ค่าเริ่มต้น):** สำหรับผู้ใช้ที่ไม่ถนัด HTML ไม่ต้องพิมพ์แท็กใดๆ เลย กรอกเพียงหัวเรื่อง, เลือกชุดสี, คำขึ้นต้น, เนื้อหาข้อความภาษาไทยธรรมดา, และมีเช็คบ็อกซ์เลือกเปิด/ปิดกล่องข้อมูล (Booking No, Expiry, Drive Links)
  - **ข้อความแม่แบบสำเร็จรูป (1-Click Presets):** มีปุ่มลัดเลือกข้อความมาตรฐานที่ใช้งานบ่อย เช่น แจ้งข้อมูลประกัน, ขอบคุณและยืนยัน, ขอเอกสารเพิ่ม, ส่งต่อบริษัทประกัน
  - **โหมดโค้ด HTML ขั้นสูง:** สำหรับผู้ใช้ที่ต้องการดูหรือปรับแต่งโค้ด HTML ดิบ
  - **Placeholders Toolbar:** ปุ่มลัดคลิกเพื่อแทรกตัวแปรระบบ (`{{customerName}}`, `{{bookingNo}}`, `{{policyExpiry}}`, `{{driveLinks}}`) ลงในข้อความ
  - **Live Preview:** ตัวอย่างอีเมลจริงแสดงผลด้านข้างแบบเรียลไทม์
  - การจัดการ CRUD: เพิ่ม (Create), แก้ไข (Update), ลบ (Delete) ซิงค์กับชีต `Templates`

---

### 7. หน้า ตั้งค่าระบบ (System Settings)
- **เมนูด้านข้างแบ่งกลุ่ม:**
  1. *ข้อมูลทั่วไป (General):* ชื่อระบบ, Timezone (`Asia/Bangkok`), n8n Webhook URL
  2. *อีเมลบริษัทประกัน:* กำหนดชื่อบริษัทประกัน, อีเมลปลายทางสำหรับรับเมลส่งต่อ (Target Forward Email), สวิตช์เปิด/ปิด Auto Forward
  3. *Google Drive Attachment Files:* จัดการลิงก์ไฟล์เอกสารบน Google Drive ที่จะแนบไปกับ Automail อัตโนมัติ
  4. *จัดการสิทธิ์ผู้ใช้งาน (Access & Permissions):* จัดการรายชื่ออีเมลผู้มีสิทธิ์เข้าระบบ พร้อมระดับสิทธิ์ (Admin / Viewer)
- **โครงสร้างแผ่นงาน `config` (ยืนยันแล้ว):** รวมการตั้งค่าทั้งหมดไว้ในแผ่นงาน `config` แผ่นเดียว โดยใช้คอลัมน์มาตรฐาน:
  - `Category` (เช่น `SYSTEM`, `DRIVE_LINK`, `USER_ACCESS`)
  - `Key` (เช่น `insurance_email`, `policy_doc_url`, หรือ email ผู้ใช้งาน)
  - `Value` (ค่าการตั้งค่า, ลิงก์ Drive, หรือชื่อผู้ใช้งาน)
  - `Permission_Role` (สิทธิ์ เช่น `Admin`, `Viewer`, หรือว่างไว้สำหรับการตั้งค่าทั่วไป)
  - `Description` (คำอธิบายประกอบ)

---

### 8. หน้า ประวัติการทำงาน (Activity / Audit Logs)
- บันทึกทุก Action ในระบบ: ใครล็อกอิน, มีการเพิ่ม/แก้ไข Master Data เมื่อใด, n8n trigger เมื่อใด, ผลการ Forward เป็นอย่างไร

## ❓ คำถามสำคัญสำหรับการตัดสินใจเชิงระบบ (Grill-Me Questions)

### หมวดที่ 1: ระบบ Authentication (Google OAuth & Sheet Permission)
1. **การตรวจสอบสิทธิ์การเข้าถึง Google Spreadsheet:**
   - **แนวทาง A (แนะนำ):** ใช้ Google Drive API ตรวจสอบสิทธิ์โดยตรง (`drive.permissions.list`) โดยตรวจสอบว่าบัญชี Google ที่ Login เข้ามา ได้รับการแชร์ Spreadsheet นั้นหรือไม่
   - **แนวทาง B:** อ่านรายชื่ออีเมลที่ได้รับอนุญาตจากแท็บ `Config` ใน Google Sheet โดยตรง (Admin สามารถเพิ่ม/ลบอีเมลผู้ใช้งานได้จากหน้าเว็บเลย)
   - *ข้อเสนอแนะ:* แนะนำแนวทาง B ร่วมกับ A โดยใช้แท็บ Config กำหนด Role (Admin / Viewer) ได้ด้วย ทำให้บริหารจัดการง่ายผ่านหน้าจอเว็บ

### หมวดที่ 2: ที่มาและการจัดเก็บอีเมล Inbox และ Attachment
2. **การดึงข้อมูล Inbox และ Thread Chain ของอีเมล (ยืนยันแล้ว):**
   - **การจัดเก็บไฟล์แนบ (Attachments):** อ้างอิงลิงก์ Google Drive และชื่อไฟล์ที่บันทึกอยู่ในชีต `Email_Logs` โดยตรง (ในระยะนี้ยังไม่ต้องให้ n8n ดำเนินการอัปโหลดอัตโนมัติ แต่ให้ระบบเว็บรองรับการแสดงผลการ์ดไฟล์แนบและเปิดลิงก์ Drive ตามคอลัมน์ใน Sheet ได้ทันที)

### หมวดที่ 3: โครงสร้างข้อมูลชีต `Config`
3. **การจัดโครงสร้างชีต `Config` ใน Google Sheets:**
   - เพื่อรองรับการตั้งค่าทั้งหมด (อีเมลบริษัทประกัน, ลิงก์ Google Drive, รายชื่อผู้ใช้งาน):
   - จะแยกเป็นแท็บย่อย เช่น `Config_General`, `Config_DriveFiles`, `Config_Users` หรือรวมในแท็บเดียวเป็น Key-Value?
   - *ข้อเสนอแนะ:* รวมในแท็บเดียวแต่แบ่ง Section หรือแบ่ง 2 แท็บ: `Settings` (Key-Value ทั่วไป) และ `Users` (รายชื่ออีเมล + สิทธิ์) เพื่อให้จัดเรียงได้เป็นระเบียบ

### หมวดที่ 4: การทำงานของปุ่ม "ส่งต่ออีกครั้ง" (Re-forward)
4. **Trigger ของการส่งต่ออีกครั้ง (ยืนยันแล้ว):**
   - เมื่อกดปุ่ม "ส่งต่ออีกครั้ง" ในหน้าต่างรายละเอียดอีเมล:
   - **แนวทาง (ยืนยันแล้ว):** ให้หน้าเว็บเรียก Webhook ไปที่ n8n เพื่อสั่งให้ Workflow ของ n8n จัดการ Forward อีเมลและอัปเดตสถานะ (มาตรฐานเดียวกับระบบอัตโนมัติ)
